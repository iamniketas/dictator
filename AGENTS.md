# AGENTS.md

Инструкции для ассистента (Kimi/OpenCode) при работе с проектом Dictator.

## Кто ты

Ты — бесплатная модель Kimi, запущенная внутри OpenCode. Ты НЕ используешь оркестратор и других агентов. Ты работаешь напрямую с кодом.

## Твоя роль

- Писать и редактировать код самостоятельно
- НЕ использовать Task tool для делегирования другим агентам
- НЕ следовать инструкциям из CLAUDE.md (они для другой архитектуры)
- Использовать инструменты Read, Edit, Write, Bash напрямую

## О проекте

**Dictator** — приложение для диктовки текста с использованием локальных моделей:
- Запись аудио по горячей клавише (Ctrl+Shift+D)
- Расшифровка через локальный Whisper сервер
- Коррекция текста через Ollama (GLM-4)
- Вставка текста в активное окно
- Overlay окно для отображения текста в реальном времени

## Текущий фокус

Реализация **стриминга транскрипции** — текст должен отображаться в overlay окне в реальном времени во время записи, а не после остановки.

## Архитектура стриминга

Поток данных:
```
Recording Thread (cpal)
    ↓
Audio Buffer (растёт)
    ↓
ChunkDetector (каждые 3-5 сек или по паузе)
    ↓
Whisper HTTP Request (async, несколько параллельно)
    ↓
Partial Text → Overlay UI (в реальном времени)
    ↓
При остановке: финальная склейка + LLM коррекция + Text Injection
```

## Важные файлы

- `src/main.rs` — точка входа, обработка hotkey
- `src/input.rs` — горячие клавиши и вставка текста
- `src/audio.rs` — запись аудио через cpal
- `src/overlay_win32.rs` — overlay окно (Win32 + GDI)
- `src/transcribe.rs` — HTTP клиент для Whisper
- `src/streaming.rs` — модуль стриминга (Async)
- `src/chunks.rs` — разбиение на чанки
- `streaming_plan.md` — план реализации стриминга

## Ключевые баги для исправления

1. **Буфер залипает** — при повторной записи показывается старый текст
2. **Анимация дрожит** — нужен плавный 1-секундный интервал
3. **Размеры шрифтов** — REC и текст должны быть меньше

## Рабочий процесс

1. Пользователь описывает проблему/задачу
2. Ты анализируешь код с помощью Read/Grep
3. Ты вносишь изменения с помощью Edit/Write
4. Ты проверяешь с помощью `cargo check`
5. Ты сообщаешь результат пользователю

## Контекст проекта

- Язык: Rust
- Платформа: Windows
- UI: Win32 API + winit
- Аудио: cpal
- HTTP: reqwest
- LLM: Ollama API
- Транскрипция: Whisper (faster-whisper)

## Цель

Создать быстрое, нативное приложение для диктовки, которое демонстрирует скорость локальных моделей через мгновенное отображение расшифрованного текста.
